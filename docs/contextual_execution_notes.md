# Contextual information assay: execution and evidence contract

The [fixed design](contextual_information_design.md) was published at commit `c23a20ec420ba19680801a09ac8b053735807d38` before implementation or pretrained outcomes. Its SHA256 is `6f50e1d3faad3240033748d7434f088ec26b7ac6716511923892e66ac0e78a09`.

The [information characterization](statebridge_information_recovery.md) is exact-arithmetic mathematics conditional on known reference information. This assay uses predetermined public probe tokens to make that condition explicit. It does not reproduce the original paper's freely generated messages, larger models or downstream task evaluation.

## Before the one empirical run

The implementation and independent offline tests are published before activation. Repository CI must pass first, with Python 3.11.18 and the same pinned Torch, transformers, NumPy, tokenizers, safetensors and huggingface-hub versions as the scientific workflow. The separately activated scientific workflow repeats the focused contracts before starting its child. Unit tests use fixed matrices and a tiny random local transformer configuration; they do not extract the planned pretrained cohort. The workspace executor was unavailable during implementation; it reconnected before activation. The executed preflight evidence comes from GitHub Actions, and no local pretrained cohort is run.

The worker will load exactly one pinned public Pythia-14M checkpoint, after checking all six files against the frozen byte hashes. It uses CPU float32, eager attention, evaluation mode and one numerical thread. The author's original Apache-licensed alignment source is preserved unchanged and only the target method's AST is executed. The GPTNeoX extraction adapter and numerical inverse are separate, explicitly reviewed code.

Public means, roots, coefficients and table conventions are constructed before private-state extraction. Captured source-dependent intermediates and true anchor IDs are evaluation evidence, not inverse inputs. The published primary criterion and all record/pair denominators remain fixed.

## Deadline and evidence

The single scientific child has a 600-second wall cap covering imports, public downloads, tokenization, all 256 eight-step extractions, numerical controls, inverses, exact integer Gram comparisons, summaries and scientific retention. The parent reuses the unchanged and previously tested process-group deadline helper. It does not continue the experiment after a timeout.

The worker persists the full plan and appends each completed or failed record. Immediate source checkpoints and subsequent numerical bundles have distinct immutable paths; a failed write cannot be counted as a confirmed retained collision. Operational errors stop further extraction after their evidence is recorded. The parent reads that evidence to identify absent, duplicate, unknown or torn records. It never repairs raw JSONL or invents a recovery. A numerical inverse rejection remains a completed observation; operational errors and missing extraction records are distinct.

The parent records exact file hashes and byte-preserving gzip receipts after the child exits. This archival time is recorded separately. Every completed or partial artifact is retained for 90 days. Permanent publication will require a separate read-only audit and packaging step, with all numerical failures and negative results preserved.

No timing or model-quality benefit is established by a successful process exit. A completed run can legitimately miss the numerical recovery target or contain no exact byte collision. Inverse failure, mathematical noninjectivity and demonstrated task-information loss have different evidentiary requirements.
